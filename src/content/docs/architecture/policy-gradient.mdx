> *When training LLMs with RLHF, rewards given by human evaluators or reward models cannot be directly backpropagated. Instead, we steer the policy by shifting the **probability mass** of sampled actions.*

### The Core Puzzle

In standard deep learning and SFT, we minimize cross-entropy loss by backpropagating error gradients directly into model weights $\theta$:

$$
\text{Prompt } s \longrightarrow \text{LLM } \pi_\theta(a|s) \longrightarrow \text{Cross-Entropy Loss } \mathcal{L} \xrightarrow{\nabla_\theta \mathcal{L}} \text{Backprop}
$$

However, in Reinforcement Learning (RLHF), the feedback loop introduces two fundamental roadblocks:

$$
\text{Prompt } s \longrightarrow \text{LLM } \pi_\theta(a|s) \xrightarrow{\text{\bf Discrete Sampling}} \text{Action } a \longrightarrow \text{\bf Black-Box Reward } R(s, a)
$$

1. **Discrete Sampling**: Generating text requires sampling concrete tokens $a \sim \pi_\theta(\cdot|s)$. Sampling is a non-differentiable operation—gradients cannot flow back through discrete choices.
2. **Black-box Reward Model**: The reward $R(s, a)$ is either a neural network score (e.g., $+8.5$) or human feedback. There is no closed-form analytical equation to differentiate a scalar score with respect to generated words.

**The Counter-Intuitive Solution**: If we cannot differentiate the reward function, **differentiate the probability of the actions that generated the reward**.

### The Minimal Math: The Log-Derivative Trick

Our objective is to maximize the expected return over trajectories $\tau$:

$$
J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)} [R(\tau)] = \int p_\theta(\tau) R(\tau) \, d\tau
$$

Differentiating under the integral:

$$
\nabla_\theta J(\theta) = \int \nabla_\theta p_\theta(\tau) R(\tau) \, d\tau
$$

Here lies the magic: apply the **log-derivative identity** ($\nabla f = f \nabla \log f$):

$$
\nabla_\theta p_\theta(\tau) = p_\theta(\tau) \nabla_\theta \log p_\theta(\tau)
$$

Substituting this back turns the integral into an empirical expectation:

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)} \left[ \nabla_\theta \log p_\theta(\tau) \cdot R(\tau) \right]
$$

Breaking trajectory probability into per-token decisions yields the **Policy Gradient Theorem**:

$$
\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)} \left[ \left( \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t | s_t) \right) R(\tau) \right]
$$

- $\nabla_\theta \log \pi_\theta(a_t|s_t)$: The direction in parameter space that increases the likelihood of action $a_t$.
- $R(\tau)$: The scalar weight modulating the update step size and direction.

<br/>

### Stabilizing the Gradient: Baseline & KL Penalty

Raw policy gradient updates suffer from extreme variance and reward hacking. Modern RLHF systems incorporate two essential stabilizers:

#### 1) Advantage Baseline ($A_t = R_t - b$)
If all rewards are positive ($R \in [1, 5]$), even mediocre actions get reinforced. Subtracting a baseline $b = \mathbb{E}[R]$ evaluates relative superiority:

$$
A(\tau) = R(\tau) - b
$$

- $A(\tau) > 0$: Outperformed average $\implies$ Increase probability ($\uparrow$)
- $A(\tau) < 0$: Underperformed average $\implies$ Suppress probability ($\downarrow$), even if $R(\tau) > 0$.

#### 2) KL Divergence Penalty ($\beta$)
To prevent the model from drifting too far from its original pre-trained/SFT distribution $\pi_{\text{ref}}$ (mode collapse):

$$
R_{\text{effective}}(\tau) = R(\tau) - \beta \cdot D_{\text{KL}}(\pi_\theta \,||\, \pi_{\text{ref}})
$$

### PyTorch Implementation

Under 30 lines of PyTorch illustrating how $\text{loss} = -(\log \pi \cdot R)$ implements gradient ascent:

```python
import torch
import torch.nn as nn
from torch.distributions import Categorical

class PolicyNetwork(nn.Module):
    def __init__(self, vocab_size=10, embed_dim=16):
        super().__init__()
        self.fc = nn.Linear(embed_dim, vocab_size)

    def forward(self, state):
        return Categorical(logits=self.fc(state))

policy = PolicyNetwork()
optimizer = torch.optim.Adam(policy.parameters(), lr=0.01)

def train_step(state, reward):
    dist = policy(state)
    action = dist.sample()             # Non-differentiable sampling
    log_prob = dist.log_prob(action)   # log pi_theta(a|s)
    
    # Negative sign because optimizer minimizes, but we want to maximize return
    loss = -(log_prob * reward)
    
    optimizer.zero_grad()
    loss.backward()                    # Propagates gradient through log_prob
    optimizer.step()
```

<br/>

### Key Takeaways

1. **Sampling breaks backpropagation**: In RLHF, rewards evaluate complete discrete sequences rather than continuous differentiable activations.
2. **Log-derivative bridges the gap**: It converts $\nabla p(x)$ into $p(x) \nabla \log p(x)$, allowing gradient calculation purely via sampled outputs.
3. **Rewards act as gradient scalers**: Good responses elevate their probability mass; bad responses suppress it.
