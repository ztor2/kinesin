[PixelRAG](https://github.com/StarTrail-org/PixelRAG)는 문서의 정보를 스크린샷, 즉 이미지 형태로 모델에 직접 학습시키고 추론하도록 한다.
이 연구는 표, 이미지와 같은 복잡한 객체를 포함한 문서를 파싱하거나 OCR을 사용해 텍스트로 변환하면, 정보가 손실될 수 있다는 것을 전제로 한다.
굉장히 새로운 접근으로 느껴졌는데, 이미 [Visual Document Retrieval](https://arxiv.org/abs/2502.18017) 나 [VisRAG](https://arxiv.org/abs/2410.10594) 같은 유사 연구가 기존에도 있었던 모양이다. 주요 로직은 아래와 같다.

![](../../../assets/images/Pasted%20image%2020260628202438.png)

- 이미지 크기의 한계가 있기 때문에 이미지를 적당한 크기(875X1024)로 타일링하여 사용한다. 
- 주요 데이터셋은 위키피디아와 뉴스 콘텐츠이며, 크롤링할 때 많이 사용하는 Playwright 헤드리스 브라우저로 웹페이지를 스크린샷으로 렌더링한다.
- 각 타일을 VLM 모델인 [Qwen3-VL-Embedding](https://github.com/QwenLM/Qwen3-VL-Embedding) 모델을 사용해 2048 차원 벡터로 임베딩한다.
- 모델 학습은 타일들을 이용해 정답을 맞추는 QA 방식으로 진행한다. 정답 / 오답 타일로 구분하여 Contrasive Learning 방식을 사용하는데, 세부 양상이 흥미롭다.
	- Contrasive Learning 은 정답 데이터(positive)는 공간 상 끌어들이고, 오답 데이터(negative)는 멀어지게 학습하는 메커니즘을 가진다. (추천시스템의 [BPR](https://arxiv.org/pdf/1205.2618) 같은 알고리즘과 유사한듯)
	- 이 연구에선 추가로 Dynamic Hard-Negative 개념을 사용하는데, 정답을 맞추는 타일과 유사하지만 정작 필요 정보는 없는 '헷갈리는' 선택지 타일들을 제공하고, 고성능 멀티모달 LLM 모델인 GPT-4o로 이를 가지고 정답을 맞추게 한다.
	- 이 Negative 타일로 LLM이 정답을 맞추면 해당 타일을 데이터에서 제거하고, 정답을 말하지 못한다고 하면 진짜 '고난이도' 타일로 선택하여 데이터에 포함시킨다.
	- 간단히 말하면 더 정교하게 오답을 걸러내는 능력을 가지도록 LLM으로 Negative 데이터를 한번 더 정제한다 - 정도로 이해할 수 있겠다.
	- '헷갈리는' 선택지 타일 후보군을 만드는 것도 일이고, LLM 비용도 소모될텐데 현실적으로 어느 정도의 효용이 있었던 건지 궁금하다. 예상보다 텍스트 방식에 비해 성능이 높게 나오진 않아 고심했던 결과는 아니었을지.. 
	- 결과적으로 성능이 향상되었더라도 이것이 시각 임베딩을 사용해서인지, 특수한 대조 학습 방법론 때문인지 조금 헷갈리는 모습이 되었다.

![511](../../../assets/images/Pasted%20image%2020260628205848.png)

- 데이터셋이 위키피디아와 뉴스 콘텐츠로 한정된 수준이어 아쉬운 부분은 있다. 연구 단계고 컴퓨팅의 한계도 있을테니 어쩔 수 없다. 
- 연구 내용과는 별개로, 직접 연구 내용을 [웹페이지 데모](https://pixelrag.ai/)로 시연할 수 있고, Claude Plugin 으로도 공개하고 심지어 API까지 개발해 공개한 것은 대단하다. AI가 대중화되면서 연구에서도 실용적인 측면이 더 발전하는 것 같다.
- 기존 RAG 방식에서 표나 이미지를 포함한 고차원 문서를 처리할 때에 어려움을 겪었던 경험이 있었는데, 이러한 고차원 문서는 별도로 시각 임베딩 처리하는 것이 좋을지도 🤔
